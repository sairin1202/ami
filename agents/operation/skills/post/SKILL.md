# 发帖

用户的账号就是用户本人的脸面，发出去的东西别人都看得到、删了也可能被截图。所以发帖分五步：**问清楚 → 起草 → 给用户过目 → 发 → 核对**，一步都别省。

## 1. 问清楚

开始写之前，这几件事要确定：

- **发到哪**：哪个平台；Reddit 要哪个版块（r/xxx），V2EX 要哪个节点，掘金要哪个分类和标签，Telegram 要哪个频道 / 群，GitHub 要哪个仓库
- **发什么**：用户给了原文就用原文；让你写就问清楚要点、立场、想达到什么效果
- **配不配图**：图片要用本机文件的路径；没有图又必须有图的平台（rednote）就用文字卡片
- **要不要话题 / 标签**

缺了关键信息就问，别猜。用户只说「帮我发一条」没说发什么，就问他想说什么。

## 2. 起草

- **用用户的口吻**，像他本人在说话，不是 AI 腔、不是营销号
- **只写用户交代的事实、观点和经历**。不编数据、不编亲身经历、不冒充身份、不夸大
- **不写成广告或引流帖**（除非用户就是要推广自己的东西，而且平台规则允许，还要写清楚是自己的东西）
- **按平台改写**，同一件事发到几个平台时每个平台的写法要不一样，不要一字不差地刷屏
- 按下面「各平台怎么发」里的长度和格式写，超了就删减，别等发的时候被截断

## 3. 给用户过目

把草稿按这个样子发给用户，等他说「发吧」「可以」再发：

> 平台：X
> 正文：……
> 图片：~/Desktop/a.png
> 话题：#xxx

- 用户已经给了**完整的原文并明确说直接发**，就不用再确认，直接发
- 用户提了修改意见就改完再给他看一遍
- **后台工作流（巡检、中控任务）里不发帖**：没人能确认，把草稿写进总结里，等用户来定
- **只让起草时**（比如中控派来的「起草帖子」任务）：做完第 2 步就停，把每个平台的草稿交回去，不打开发帖页、不发

## 4. 发

各平台怎么发：

| 平台 | 用什么 | 限制和格式 |
|---|---|---|
| rednote（小红书国际版） | `rednote_publish`（title, body, card_text） | 只能发纯文字笔记：card_text 生成图片卡片；标题 ≤ 20 字，正文 ≤ 1000 字，话题写成 `#话题` 放在正文末尾 |
| 小红书国内版 | `xhs_write` 的 `post`（只有设了 XHS_SITE=xiaohongshu 时才有） | `--title` `--body` `--images 图片路径`（可以写多个），`--topic` 话题，`--private` 仅自己可见 |
| X / Twitter | 浏览器：`browser_open` 打开 https://x.com/compose/post ，在输入框写好，点「Post / ポストする」（界面可能是中 / 英 / 日文） | 普通账号单条 ≤ 280 字符，中文算 2 个（≈ 140 个汉字）；最多 4 张图；长内容拆成串：发完第一条，在它下面回复接着写。新注册的账号可能被要求验证手机 / 邮箱，遇到就停下让用户处理 |
| B 站动态 | `bili_write` 的 `dynamic-post` | 纯文字动态 |
| GitHub | `github_create_issue` / `github_comment` | 用 Markdown；提 issue 先搜有没有重复的（`github_search`），按仓库的 issue 模板写 |
| Telegram 频道 / 群 | 用户本人账号用 `tg_write` 的 `send`；机器人用 `telegram_send` | 聊天名要和 `tg chats` 里的完全一致 |
| Reddit、LinkedIn、知乎、即刻 | 浏览器：`browser_open` 打开发帖页，照网站规则里写的按钮操作 | Reddit 先读版块侧栏的版规（Rules），选好必需的 flair；LinkedIn、知乎对自动化管得严，别连着发 |
| V2EX | 浏览器：`browser_open` 打开 https://www.v2ex.com/write ，选节点、填标题和正文（格式选 Markdown），点「发布主题」 | 标题 ≤ 120 字；自己做的东西只发「分享创造」（create），广告只发「推广」（promotions）；同一个产品一般只发一次，写动机和技术，不写 AI 腔 |
| 少数派 | 浏览器：`browser_open` 打开 https://sspai.com/write ，填标题、正文、头图，点「发布」（发到 Matrix 社区） | 长文，讲清楚解决什么问题、怎么用、配截图；投稿给编辑部上首页要先问用户；软文会被移出首页 |
| 掘金 | 文章：`browser_open` 打开 https://juejin.cn/editor/drafts/new?v=2 ，写 Markdown，点「发布」后选分类、至少一个标签、写摘要，再点「确定并发布」；短动态：在 https://juejin.cn/pins 发沸点 | 技术社区：写实现思路和技术细节；文章发完要审核（显示审核中），核对时说明还在审核 |
| 评论 / 回复 | rednote：`xhs_write` 的 `comment` / `reply`；X 和其他网站都在浏览器里，在帖子页的回复框写好点「Reply / 回复」 | 同样的评论不要发到多篇帖子下面 |

- **一次只发一个平台**，发完一个、核对完再发下一个
- 同一个平台短时间内不要连发好几条，容易被风控
- 要登录、弹验证码、要绑手机，就停下来让用户自己处理；不输密码，不点付费 / 订阅

## 5. 核对

- 拿到帖子的 id 或链接；能读回来就读回来确认发出去了、内容对（rednote 用 `xhs` 的 `read`；X 和其他网站发完看页面上有没有出现这条，再打开自己的主页确认）
- **发失败了先查是不是其实已经发出去了**，确认没发出去再重试，绝不能重复发
- 最后告诉用户：发到了哪、链接是什么、有没有和草稿不一样的地方（比如被截断、图片没传上）
